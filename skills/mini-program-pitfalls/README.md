# Common Pitfalls for Early-Stage Mini-Program Development

> 25 个上线前后反复出现的坑，按"通道 → 运行时 → 数据"分层，每条给症状、根因和**判据**；
> 末尾是一份带验证步骤的上线前清单。
> Twenty-five failures that look random until you see the layer, plus a launch checklist.

## 这套材料的来源

来自两个真实小程序从 0 到上线的过程：一个跑在云开发（云函数 + 云数据库），一个跑在自建 Node
（单进程 + 文件存储）。两套架构完全不同，但踩的坑高度重合——**重合的部分才是通用知识**。

所以这份文档只保留两边都验证过的结论，去掉具体业务：

- 没有项目名、品牌、门店、商品
- 没有真实域名、IP、密钥、商户号
- 所有示例都是占位符

## 三层模型（先记住这个）

| 层 | 你以为它在管什么 | 实际在管什么 | 症状 |
|---|---|---|---|
| 运行时 | 你的代码 | 配额、冷启动、超时、进程存活 | 白天好，深夜挂 |
| 数据 | 你写进去了 | 谁能写、并发谁赢、写坏怎么恢复 | 总数对不上、记录丢 |
| 通道 | 接口能通 | 备案、白名单、协议、缓存 | 开发者工具正常，真机死 |

排查顺序：**通道 → 运行时 → 数据**。反过来做最费时间，因为通道坏了长得像业务 bug。

## 最贵的五个坑

| 坑 | 后果 |
|---|---|
| 把"接口返回 200"当成"钱到了" | 账本虚报，用户没收到钱 |
| 重试换了退款单号 | **真的退两笔** |
| 提现遇到超时就回滚余额 | 用户能凭同一笔余额提两次 |
| 没有定时兜底 | 中间态订单永远堆着，只能人工 |
| 客户端直接改库存/状态 | 并发丢更新，谁都能绕过界面 |

## 怎么用

1. 先读 `SKILL.zh-CN.md` 或 `SKILL.md`（同一份内容，中英各一版）
2. 要上线了，直接翻到清单，逐项打勾；`references/launch-checklist.md` 有打印版
3. 只有一小时：先验清单里的 A7、C1、C2、B3、D1、E4 这六项
